01Introduction and objectives

Moobilia is a responsive furniture-store website built from scratch with HTML and CSS only. It is the final exam project of the Web Development module: a complete multi-page website that reproduces a professional UI design, with every interaction written in pure CSS and published online with GitHub Pages.

The project had four objectives:

  • Build a faithful, pixel-careful implementation of the design on desktop, tablet and phone.
  • Implement all interactions (category tabs, carousels, sticky header, burger menu, scrollbars, add-to-cart buttons) without JavaScript.
  • Write clean, well-structured and commented code, with one shared stylesheet for all pages.
  • Document the development steps, the choices made and the techniques used (this report).

03Design choices

The identity is minimal and calm: white pages, dark text and one strong orange accent, so the furniture photographs remain the focus.

TokenValueUse
Orange#e58411Accent: labels, links, buttons, scrollbars
Soft orange#f6973fHover states, footer column titles
Navy#0d1b39Product names, prices, call-to-action bands
Ink#1e1e1eMain text and headings
Light grey#f7f7f7Section and card backgrounds
  • Typography: Gilroy Bold / Medium / Regular, loaded locally with @font-face (font-display: swap avoids invisible text); Inter and DM Sans from Google Fonts for product cards and the footer.
  • Design tokens: colours, fonts, gutters and scrollbar sizes are CSS custom properties declared once in :root. Changing the theme means editing one block.
  • Layout: CSS Grid for page layouts (header, "Why pick us", feature sections, statistics, product grid, footer); Flexbox for rows and carousels.
  • Depth: rounded corners, soft shadows, backdrop-filter blur (frosted glass) and blurred copies of photos used as colour glows.

05Development process

The work followed six phases, from analysis to publication.

AnalysisStudy the design, list pages, sections, colours, fonts and interactions.
StructureWrite the semantic HTML of the home page, then of the four secondary pages.
StylingBuild the CSS: tokens, layout, typography, cards and effects.
InteractionsTabs, carousels, burger menu, add-to-cart buttons, sticky header and scrollbars in pure CSS.
UnificationMerge the four page stylesheets into styles.css and reuse the same header and footer everywhere.
Test & publishCheck three screen sizes, fix issues, add SEO / sharing tags, push to GitHub and enable Pages.

Unification step in detail. The secondary pages first had their own style.css and a simplified header and footer. They were merged into one stylesheet (a dedicated "secondary pages" section), the duplicated rules were removed, and the pages now use exactly the same .site-header and .footer markup and classes as the home page. Only one modifier class was added, .is-solid, because these pages have no dark hero behind the header.

How styles.css is organised

The file is split into clearly labelled sections, in the order of the page: fonts → variables → scrollbar → base → header → hero → why → shop → carousel → product card → features → testimonials → footer → secondary pages → responsive rules → accessibility.

Conventions

  • Short, descriptive class names with prefixes by component (pcard-* product card, tcard-* testimonial card, f-* footer).
  • Every section starts with a banner comment; non-obvious techniques have a short explanation next to the rule.
  • No duplicated rules: shared components (buttons, cards, header, footer) are defined once. The same product card (.pcard) is used in the home carousels and in the catalogue grid of the "view-all" page.
  • HTML pages use the same landmark structure and the same comments (EN-TÊTE, PIED DE PAGE …).
  • Relative paths only, so the site works from any folder or from GitHub Pages.

07Key technical solutions

This chapter explains the main techniques. All of them work without a single line of JavaScript.

7.1 Category tabs with :has()

Each tab is a hidden radio button plus a styled label. The :has() selector lets the whole section react to the checked radio, so the product carousel is replaced by a message for categories without products yet.

<!-- HTML -->
<input class="tab-radio" type="radio" name="cat" id="t-beds">
<label class="tab" for="t-beds">Bedroom</label>

/* CSS */
.shop:has(#t-beds:checked) .shop-carousel { display: none; }
.shop:has(#t-beds:checked) .shop-empty    { display: block; }

7.2 Header that changes while scrolling

A scroll-driven animation is tied to the page scroll position. During the first 140 px the header turns white and shrinks. Browsers without support keep the transparent header, so nothing breaks.

@supports (animation-timeline: scroll()) {
  .site-header { position: fixed; animation: hdr linear both;
                 animation-timeline: scroll(root); animation-range: 0 140px; }
  @keyframes hdr { to { background: rgba(255,255,255,.96); color: #1e1e1e; } }
}

7.3 Custom overlay scrollbar

The native scrollbar is hidden and replaced by an orange pill drawn with body::after. The same scroll timeline moves it from top to bottom, so it always shows the scroll position and does not take any page width.

html { scrollbar-width: none; }            /* hide native bar */
body::after { content: ""; position: fixed; right: 6px; width: 10px; height: 140px;
  border-radius: 999px; background: #e58411; pointer-events: none;
  animation: sb-move linear both; animation-timeline: scroll(root); }
@keyframes sb-move { from { transform: translateY(8px); }
  to { transform: translateY(calc(100dvh - 140px - 8px)); } }

7.4 Carousels with scroll-snap and a progress bar

The track is a horizontal flex row. scroll-snap aligns the cards; scroll-timeline on the track and timeline-scope on its parent let a bar under the carousel follow the horizontal scroll.

.carousel { position: relative; timeline-scope: --trk; }
.track    { display: flex; overflow-x: auto; scroll-snap-type: x mandatory;
            scroll-timeline: --trk x; scrollbar-width: none; }
.carousel::after { content: ""; position: absolute; bottom: 0; width: 140px; height: 8px;
  background: #e58411; border-radius: 999px;
  animation: hsb-move linear both; animation-timeline: --trk; }
@keyframes hsb-move { to { left: calc(100% - 140px); } }

7.5 Burger menu without JavaScript

A hidden checkbox stores the menu state. The label is the burger button and the sibling selector shows the menu under 900 px. The three bars turn into an "X" with CSS transforms.

<input type="checkbox" id="navCheck" class="nav-check">
<label for="navCheck" class="nav-toggle"><span></span><span></span><span></span></label>
@media (max-width: 900px) {
  .nav { display: none; }
  .nav-check:checked ~ .nav { display: flex; }
}

7.6 One header and one footer for all pages

The secondary pages reuse the home page markup. A small modifier makes the header permanently white because these pages start with a light background instead of a dark photo.

.site-header.is-solid { position: fixed; animation: none;
  background: rgba(255,255,255,.96); color: var(--ink); }
.site-header.is-solid .chev, .site-header.is-solid .bag { filter: invert(1); }

7.7 Add-to-cart button and design tokens

The "+" button is a checkbox + label: when checked it turns from navy to orange. Colours and sizes come from variables (--orange, --navy, --gutter), which the media queries override (for example --gutter: 80px on desktop, 48px on laptops, 24px on phones).

08Responsive design and accessibility

BreakpointWhat changes
≤ 1280 pxSmaller gutters and section spacing, fluid hero title with clamp(), "Why pick us" in three columns, footer grid adapts.
≤ 1180 pxCarousels show three then two cards; product grid in three columns.
≤ 1024 pxSecondary hero columns get closer, titles shrink to 44 px.
≤ 900 pxBurger menu, hotspots hidden, one-column layouts, two-column product grid, statistics in 2×2.
≤ 480 pxSingle-column product grid, tabs fill the width.
  • Fluid units (clamp(), percentages, aspect-ratio) avoid fixed heights that would break on small screens.
  • Images have alt text; purely decorative images use alt="".
  • Visible hover and focus states; the add-to-cart buttons are real form controls usable with the keyboard.
  • prefers-reduced-motion turns off smooth scrolling and the pulse animation for users who ask for less motion.

09Testing and compatibility

Each of the five pages was checked in Chromium at three widths (1440, 820 and 390 px): no missing file, no horizontal scrolling, header and footer identical on every page.

FeatureChrome / EdgeFirefox / Safari
Layout, Grid, Flexbox, tabs (:has())SupportedSupported (recent versions)
Scroll-snap carouselsSupportedSupported
Sticky header animationSupportedFalls back to the plain header
Orange page and carousel scrollbarsSupportedNot drawn (scrolling still works)

Known limitation. Scroll-driven animations are not yet available in every browser. In those browsers the native scrollbar is hidden and the orange bar is not drawn, so the page scrolls normally but without a visible indicator. A possible improvement is to hide the native scrollbar only inside an @supports (animation-timeline: scroll()) block.

10Performance, SEO and sharing

  • Every page has a unique title, a description, a theme colour and favicons.
  • Open Graph and Twitter card tags (og:title, og:description, og:url, og:image 1200×630 …) give a rich preview when the link is shared.
  • Scripts: none. Fonts use font-display: swap; external fonts use preconnect.
  • Point to improve: the product images are large PNG files (several MB each). Resizing them and converting to WebP would greatly reduce the loading time.

11Deployment on GitHub Pages

  1. Create a public repository and upload the project folder, keeping index.html at the root.
  2. Open Settings → Pages, choose Deploy from a branch, branch main, folder / (root), then Save.
  3. After a minute the site is online at https://<user>.github.io/<repository>/.
  4. Replace the placeholder address in the Open Graph tags (og:url, og:image, canonical) with this real address.

Because all paths are relative, no other change is needed.

13Conclusion and future work

The project reaches its goals: a fast, accessible and fully responsive five-page website that matches the design, written with a single stylesheet, shared header and footer, and no JavaScript. It strengthened our skills in modern CSS, responsive design, code organisation and teamwork with Git.

  • Add a real shopping cart (JavaScript) and a working search.
  • Add product detail pages and a contact page.
  • Compress images (WebP) and add lazy loading.
  • Make the scrollbar fallback work in every browser.
  • Add dark mode and a French / Arabic version.
